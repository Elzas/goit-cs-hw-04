# goit-cs-hw-04 — Паралельний пошук ключових слів у текстових файлах

`main.py` шукає ключові слова у `.txt` файлах двома способами і порівнює час:

- **Threading** — файли діляться між 4 потоками (`Thread`), кожен потік шукає слова у своїй частині, результати збираються у спільний словник під `RLock`;
- **Multiprocessing** — файли діляться між 4 процесами (`Process`), кожен процес кладе свій словник результатів у `Queue`, головний процес їх об'єднує.

Обидві версії повертають словник `{ключове слово: [шляхи до файлів]}`.

Тестові дані — тексти пісень Placebo з альбому *Black Market Music* (2000) у папці `files/`.

## Запуск

```bash
python main.py                      # папка files, слова heart never time dream
python main.py files love night     # своя папка і свої слова
```

## Обробка помилок

- папка не існує або в ній немає `.txt` — програма завершується з повідомленням;
- файл не читається (`OSError`: немає доступу, файл зник) — записується в лог, файл пропускається, пошук триває;
- файли читаються з `errors="ignore"`, тому некоректне кодування не ламає пошук;
- пошук не залежить від регістру.

## Результати

На macOS: Threading ≈ 0.001 c, Multiprocessing ≈ 0.1 c.

Пошук у файлах — IO-bound задача, тому потоки справляються швидко навіть попри GIL. Процеси програють, бо на macOS вони створюються методом `spawn`: для кожного процесу заново запускається інтерпретатор Python, імпортуються модулі, а результати серіалізуються через `Queue`. На невеликому наборі файлів ці накладні витрати набагато більші за саму роботу. Перевага процесів проявляється на великих обсягах тексту, коли основний час іде на обробку даних (CPU-bound), а не на їх читання.
